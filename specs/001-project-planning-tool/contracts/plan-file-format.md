# Contract: 原生文件格式 `.mcm`

**决策**: 原生文件 = 大纲文本本身（[outline-grammar.md](./outline-grammar.md)）
加 `%mcm` 版本头。"用户手打的输入语言"与"磁盘格式"是同一份文法——所见即所存
（宪法 V；决策记录 research.md R4）。
**落位**: `crates/mcm-core/src/session.rs` + `outline/`

## 基本约定

| 项 | 约定 |
|----|------|
| 扩展名 | `.mcm` |
| 编码 | UTF-8，无 BOM；换行 LF（读取时容忍 CRLF，保存归一为 LF） |
| 首行 | `%mcm 1`（格式主版本） |
| 正文 | 大纲文法全文 |

## 版本策略

- 主版本相同 → 正常打开。
- 主版本更高（未来文件）→ 拒绝打开，明确提示"需要更新应用"；绝不静默降级或改写。
- 缺失版本头 → 按 v1 尽力解析，报 P-001（Warning 级提示补头），保存时自动补写。
- 未来新增语法必须保持"旧应用可识别为未知指令/注解并保留原文"的加法式演进。

## 规范化与人工编辑

- 应用保存的文件恒为规范化形态（canonical form）：稳定顺序、2 空格缩进、恒写 ID、
  单尾换行 → 行级 diff 稳定、可 Git 合并（宪法 V）。
- 人工编辑的合法变体（注解乱序、多余空行、CRLF）在打开时接受，下次保存归一化。
- 注释（`#` 行）与备注（`>` 行）永不丢失：随归属元素回写。

## 原子保存（Edge case: 断电/强退不损坏）

1. 序列化到同目录临时文件 `.<name>.mcm.tmp-<rand>`；
2. `fsync` 临时文件；
3. `rename` 覆盖目标路径（同卷原子）；
4. 失败任一步 → 保留原文件不动，报错给用户。

## 恢复语义（spec FR-015 / US4-3）

- 解析按行推进；无法解析的行被**隔离**：以 `P-*` 问题（含行号与原文）呈现在问题
  面板，并在模型上附"隔离内容"清单；其余行正常入模型。
- 隔离内容在保存时以注释形式 `# [mcm:recovered] <原文>` 写回文件尾——内容永不
  静默丢失，用户可手工处置。
- ZIP/二进制等完全不可读文件 → 拒开并给出明确错误（不是恢复场景）。

## 外部修改（Edge case）

- 会话期间监测文件 mtime；发现外部变更 → 提示"重新加载 / 保留内存版本"，
  绝不静默覆盖任一方。

## 视图状态

- 折叠状态、缩放、当前视图等 UI 状态**不写入** `.mcm`（保持文件纯内容、diff 干净），
  存应用数据目录 `prefs.json`（按文件路径索引）。

## 契约测试要求（合入门槛）

1. 往返：任意模型 保存→打开 相等（含 100 次随机编辑后，对应 spec SC-006）。
2. 原子性：注入 rename 前崩溃 → 原文件完好。
3. 恢复：对 fixtures 注入行级损坏 → 打开成功、隔离清单正确、保存后 `[mcm:recovered]`
   注释在场。
4. 版本：`%mcm 2` 文件 → 拒开且提示准确；无头文件 → 打开 + P-001 Warning。
5. CRLF/BOM/乱序注解输入 → 打开成功，保存后为规范化形态。
