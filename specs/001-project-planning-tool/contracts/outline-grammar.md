# Contract: 大纲语言文法（Outline Grammar v1）

**用途**: 用户录入项目描述的输入语言，同时是 `.mcm` 原生文件的正文（见
[plan-file-format.md](./plan-file-format.md)）。解析必须完全确定：同一文本必得同一模型。
**落位**: `crates/mcm-core/src/outline/`

## 示例（完整合法文档）

```text
%mcm 1
%title 移动端改版
%start 2026-09-01

# 第一阶段
- 需求阶段 #t1 @王芳
  - [x] 用户访谈 #t2 [2026-09-01..2026-09-05]
  - 竞品分析 #t3 [3d] <-t2
    > 重点看 A、B 两家的任务视图
  - 需求评审 #t4 [1d] <-t2 <-t3
- 设计阶段 #t5
  - 交互稿 #t6 [5d] <-t4
! 需求冻结 #m1 [2026-09-10] <-t4
```

## 行类型

| 行 | 语法 | 说明 |
|----|------|------|
| 版本头 | `%mcm 1` | 保存文件的首个非空行必须是它；应用内临时输入可省略（按 v1 解析） |
| 指令 | `%title <text>` / `%start <date>` / `%desc <text>` | 各至多一次；未知 `%` 指令 → P-008（Warning，保留原文） |
| 注释 | `# <text>` | 整行注释；归属到下一元素（文件尾注释归属 Plan），保存时原样回写 |
| 任务 | `<缩进>- [x]? <标题与注解>` | 缩进 = 每层 2 空格；`[x]` 完成 / `[ ]` 未完成（可省） |
| 备注 | `<父任务缩进+2>> <text>` | 归属上方最近任务；连续多行拼接（保留换行） |
| 里程碑 | `! <名称> #id? [<date>] <-tN ...` | 仅顶层（缩进 0）；日期必填（P-006） |
| 空行 | | 忽略（规范化时按节保留一处） |

## 任务行注解（token 级，空白分隔）

| 注解 | 语法 | 语义 |
|------|------|------|
| 标识 | `#t<n>`（任务）/ `#m<n>`（里程碑） | 稳定 ID；缺省由解析器按文档序分配下一个空闲号；重复 → V-DUP |
| 日期 | `[YYYY-MM-DD..YYYY-MM-DD]` | 显式起止（含端点）；start ≤ end 否则 V-RANGE |
| 工期 | `[<N>d]` | N ≥ 1 个工作日（周末非工作日） |
| 负责人 | `@<text>` | 自由文本，至空白截止 |
| 前置 | `<-t<n>` | 本任务的前置任务（依赖方向 t\<n\> → 本任务，与依赖图箭头一致）；可重复 |

规则：注解 token 可出现在标题词之间任意位置，但**规范化保存时固定顺序**（见下）；
剥离注解后的剩余文本为标题，必须非空（V-TITLE）。要在标题里书写字面 `#`/`@`/`[`/`<-`
开头的词，用反斜杠转义（如 `\#hashtag`）；规范化保存时自动补转义。

## 时间推导（确定性，供时间线视图与 V-ORDER/V-PARENT/V-MSTONE）

1. `Explicit{start..end}` 直接生效。
2. `Duration{Nd}`：start = 所有前置 `effective_end` 的最大值的下一工作日；无前置则取
   `%start`（再缺省为打开当日）；end = start 起第 N 个工作日（跳过周六日）。
3. 父任务无显式日期时，取全部子任务有效区间的包络。
4. 叶子且无任何日期信息 → 无日期（时间线视图给 W-NODATE）。

推导在 V-CYCLE 通过后按拓扑序单遍完成；任何输入下结果唯一。

## 解析错误码（P-*，Error 除非注明；均含行/列定位与修复指引）

| 码 | 条件 |
|----|------|
| P-001 | 保存文件缺失或非法 `%mcm` 版本头；主版本高于当前支持 → 拒开并提示升级 |
| P-002 | 缩进非 2 的倍数，或层级跳变 > 1（如从 0 层直接到 2 层） |
| P-003 | 日期/工期格式非法（含 `[..]` 区间写反语法） |
| P-005 | 注解语法非法（`#`/`<-` 后不是合法 ID 形式等） |
| P-006 | 里程碑行缺少 `[日期]` |
| P-007 | `>` 备注行找不到所属任务 |
| P-008 | 未知 `%` 指令（**Warning**；内容保留） |

行级恢复：出错行不中断解析——该行按 [plan-file-format.md](./plan-file-format.md)
§恢复 隔离，其余内容正常入模型（spec FR-015）。

## 规范化序列化（canonical form）

- 顺序：版本头 → 指令（title/start/desc）→ 空行 → 任务森林（文档序，深度优先）→
  里程碑；文件以单个换行结尾。
- 任务行内顺序：`- ` → `[x] `（如完成）→ 标题 → `#id` → `[日期/工期]` → `@负责人`
  → `<-前置`（按 ID 升序）。
- ID 恒写出（保证跨会话稳定引用）；缩进 2 空格；注释与备注紧随其归属元素回写。
- 往返律（属性测试守护）：`parse(serialize(m)) == m`；对规范化文本
  `serialize(parse(t)) == t`。

## 契约测试要求（`mcm-core` 内，合入门槛）

1. Golden 测试：`fixtures/outline/*.mcm` ↔ 模型快照双向断言（含本页示例）。
2. 属性测试：随机模型 → 序列化 → 解析 → 相等；随机行级损坏 → 解析不 panic、
   恢复计数正确。
3. 错误码测试：每个 P-*/相关 V-* 至少一个最小触发样例，断言码、行列、修复指引非空。
4. 确定性测试：同一输入解析 100 次，模型与 ID 分配完全一致。
