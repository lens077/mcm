# Feature Specification: 项目规划桌面工具（生成、校验、交互编辑与可编辑导出）

**Feature Branch**: `001-project-planning-tool`

**Created**: 2026-08-26

**Status**: Draft

**Input**: User description: "项目规划桌面工具：用户（开发者/产品经理）输入项目描述，生成经校验的可交互规划视图（任务分解、依赖、里程碑、时间线），支持编辑并导出为 XMind (.xmind) 与 Visio (.vsdx) 可继续编辑的文件"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 录入项目描述并生成经校验的规划 (Priority: P1)

产品经理或开发者以结构化大纲（缩进表达任务层级，简洁标记表达日期、依赖、里程碑与
负责人）录入项目描述，系统经确定性解析生成一份统一的项目规划：任务分解层级、
任务间依赖、里程碑与时间线。生成前必须通过确定性校验；存在问题时，
系统给出定位到具体元素的问题清单，而不是呈现一份"看起来正常"的错误规划。

**Why this priority**: 这是产品的起点与核心价值——没有"描述 → 经校验的规划"，
后续查看、编辑、导出都无从谈起。仅此一项即可构成可演示的 MVP。

**Independent Test**: 录入一份包含层级任务、依赖、里程碑与日期的项目描述，
验证生成的规划完整、正确，且注入的错误（循环依赖、日期矛盾）全部被定位报告。

**Acceptance Scenarios**:

1. **Given** 空白项目, **When** 用户录入包含任务层级、依赖、里程碑与日期的项目描述并触发生成, **Then** 系统呈现完整规划且校验通过，无错误项
2. **Given** 描述中含循环依赖（A→B→C→A）, **When** 触发生成, **Then** 系统报告循环依赖错误，指出完整环路径并定位到相关任务
3. **Given** 描述中子任务日期超出父任务日期范围, **When** 触发生成, **Then** 校验报告指出具体冲突元素并给出修复建议
4. **Given** 描述中引用了不存在的任务（如依赖指向未定义任务）, **When** 触发生成, **Then** 系统报告引用完整性错误并定位到出错位置

---

### User Story 2 - 四种联动视图交互查看 (Priority: P1)

用户在四种视图间自由切换查看同一份规划：任务分解（树/大纲）、依赖网络、里程碑、
时间线。视图间选中状态联动，支持搜索定位、缩放平移，并提供深色与浅色主题。

**Why this priority**: 多视角查看是"规划工具"区别于"文本清单"的核心体验，
也是用户理解项目结构的主要途径。

**Independent Test**: 对一份已生成的规划，逐一验证四种视图的呈现正确性、
跨视图选中联动与搜索定位。

**Acceptance Scenarios**:

1. **Given** 已生成的规划, **When** 在任一视图选中任务 X 后切换到其他视图, **Then** X 在新视图中保持选中并自动定位可见
2. **Given** 含 1,000 个任务的规划, **When** 缩放、平移、切换视图, **Then** 交互全程无可感知卡顿
3. **Given** 任一视图, **When** 按关键词搜索任务, **Then** 匹配任务高亮并可逐个跳转定位
4. **Given** 任一视图, **When** 切换深色/浅色主题, **Then** 所有视图元素在两种主题下均清晰可辨

---

### User Story 3 - 在视图中直接编辑并即时重校验 (Priority: P1)

用户直接在视图中修改规划：增删改任务、拖拽调整层级、建立或断开依赖连线、
调整日期与里程碑。每次编辑后系统即时重新校验，问题以非阻断方式标注在相关元素上；
所有操作可撤销、可重做。

**Why this priority**: 规划是活文档，"生成后可编辑"是用户采纳本工具做日常管理的前提。

**Independent Test**: 在已生成的规划上执行全类型编辑操作，验证跨视图同步、
即时校验标注与撤销/重做链的正确性。

**Acceptance Scenarios**:

1. **Given** 打开的规划, **When** 在任务分解视图新增、重命名、删除任务或拖拽调整层级, **Then** 变更立即同步反映在所有视图
2. **Given** 依赖网络视图, **When** 从任务 A 拖出连线到任务 B, **Then** 建立 A→B 依赖；若该依赖成环，系统标注错误并展示环路径
3. **Given** 某次编辑引入校验问题, **When** 编辑完成, **Then** 问题即时标注于相关元素并汇总于问题面板，但不阻断用户继续编辑
4. **Given** 一系列编辑操作, **When** 逐步撤销与重做, **Then** 规划状态精确回退与前进，无残留或丢失

---

### User Story 4 - 本地保存与无损重开 (Priority: P1)

用户把规划保存为本地文件，之后重新打开完全还原。文件是人类可读、可手工编辑、
可进入版本控制系统比对的文本格式；文件部分损坏时尽力恢复并如实报告。

**Why this priority**: 桌面工具的数据底座。无可靠的本地持久化，编辑与导出均不可信。

**Independent Test**: 保存-重开往返比对；用文本编辑器手工修改文件后重新打开验证；
构造部分损坏文件验证恢复与报告行为。

**Acceptance Scenarios**:

1. **Given** 编辑后的规划, **When** 保存并重新打开, **Then** 规划内容与结构完全还原，无任何丢失或漂移
2. **Given** 已保存的文件, **When** 用户以纯文本编辑器查看或修改, **Then** 内容结构清晰可读，合法的手工修改在重新打开后生效
3. **Given** 部分损坏的文件, **When** 打开, **Then** 系统恢复可解析的部分，并明确报告被丢弃或存疑的内容
4. **Given** 存在未保存更改, **When** 用户关闭应用, **Then** 系统提示保存，用户可保存、放弃或取消关闭

---

### User Story 5 - 导出 XMind 并可继续编辑 (Priority: P2)

用户将规划导出为 .xmind 文件，在 XMind 中打开得到结构完整的脑图：任务层级、
名称、备注与里程碑标记均为可编辑对象，可在 XMind 中继续调整并正常保存。

**Why this priority**: 可再编辑导出是本产品对外协作的核心承诺之一；
依赖 P1 的模型与校验先行。

**Independent Test**: 导出后在 XMind 中打开、编辑、再保存，比对结构与文本零丢失。

**Acceptance Scenarios**:

1. **Given** 校验通过的规划, **When** 导出为 .xmind, **Then** 文件在 XMind 中成功打开，任务层级、名称、备注、里程碑标记完整呈现为可编辑脑图节点
2. **Given** 在 XMind 中打开的导出文件, **When** 编辑节点文本、调整结构并保存, **Then** XMind 正常保存无报错，无不可编辑的图片替身
3. **Given** 规划中存在目标格式无法原生表达的信息（如依赖关系）, **When** 导出, **Then** 该信息以约定的降级方式承载（如标签/备注），并在导出摘要中逐项列明

---

### User Story 6 - 导出 Visio 并可继续编辑 (Priority: P2)

用户将规划导出为 .vsdx 文件，在 Visio 中打开得到依赖网络图（并含里程碑与
时间线信息）：任务为形状、依赖为保持逻辑连接的连接线，全部可继续编辑。

**Why this priority**: 面向使用 Office 生态的干系人交付；同样依赖 P1 模型先行。

**Independent Test**: 导出后在 Visio 中打开，移动形状验证连线跟随，编辑并再保存
验证无损坏警告。

**Acceptance Scenarios**:

1. **Given** 校验通过的规划, **When** 导出为 .vsdx, **Then** 文件在 Visio 中成功打开：任务为形状、依赖为连接线、文本完整，连线与形状保持逻辑连接（移动形状时连线跟随）
2. **Given** 在 Visio 中打开的导出文件, **When** 移动形状、编辑文本并保存, **Then** 操作正常完成，无文件损坏或修复警告
3. **Given** 规划中存在目标格式无法表达的信息, **When** 导出, **Then** 信息按约定降级承载，并在导出摘要中逐项列明

---

### Edge Cases

- 空描述或仅有项目名：生成最小合法规划并提示补充内容，不得产出错误状态或崩溃
- 大纲中存在无法识别的语法或标记：报告定位到具体行的解析错误，不得静默生成部分错误的规划
- 循环依赖（含长环）、父任务与其子任务之间的依赖等非法结构如何报告
- 日期矛盾：依赖双方时序颠倒、子任务超出父任务范围、里程碑早于其全部前置任务完成
- 超大规划（≥1,000 任务、密集依赖）下的生成、渲染、编辑与导出表现
- 极长任务名、特殊字符与表情符号在本工具及 XMind/Visio 打开后的完整性
- 导出目标位置不可写、文件被目标工具占用时的明确错误与重试指引
- 规划文件被外部程序修改后在本工具中重新加载的行为（提示重载而非静默覆盖）
- 撤销跨越"重新生成"边界：重新生成后撤销应能回到生成前状态
- 磁盘写入中断（断电/强退）后已保存文件不得整体损坏

## Requirements *(mandatory)*

### Functional Requirements

**生成与校验**

- **FR-001**: 系统 MUST 允许用户以结构化大纲录入项目描述（缩进表达任务层级，简洁标记表达日期、工期、依赖、里程碑与负责人），并经确定性解析生成完整规划；同一描述 MUST 始终生成同一规划；解析与生成 MUST 完全离线完成
- **FR-002**: 系统 MUST 以统一的规划模型承载任务层级、依赖、里程碑、时间线与负责人；所有视图 MUST 呈现同一模型，视图间不得出现事实分歧
- **FR-003**: 系统 MUST 在生成与每次编辑后执行确定性校验，至少覆盖：引用完整性、依赖无环、日期一致性（依赖时序、父子日期包含、里程碑约束）
- **FR-004**: 每条校验问题 MUST 定位到具体元素、说明原因并给出修复指引；全部问题 MUST 可在汇总面板中浏览并跳转
- **FR-005**: 系统 MUST NOT 呈现无法回溯到规划模型事实的内容；渲染结果由模型唯一决定

**视图与交互**

- **FR-006**: 系统 MUST 提供四种视图：任务分解（树/大纲）、依赖网络、里程碑、时间线
- **FR-007**: 视图间 MUST 联动：同一元素的选中状态跨视图保持并自动定位
- **FR-008**: 用户 MUST 能按关键词搜索任务并逐个跳转定位
- **FR-009**: 系统 MUST 提供深色与浅色主题；核心操作 MUST 键盘可达

**编辑**

- **FR-010**: 用户 MUST 能在视图中直接编辑：任务增删改、层级拖拽调整、依赖连线建立与断开、日期与里程碑设定、负责人指定
- **FR-011**: 校验问题 MUST 以非阻断方式即时标注；存在校验错误时执行导出，系统 MUST 明确警示后方可继续
- **FR-012**: 撤销/重做 MUST 覆盖所有编辑与生成操作，状态回退精确无残留

**文件与数据**

- **FR-013**: 系统 MUST 将规划保存为本地文件；格式 MUST 人类可读、可手工编辑、可逐行比对，并包含格式版本标识
- **FR-014**: 保存后重新打开 MUST 无损还原（往返一致）
- **FR-015**: 打开部分损坏的文件时，系统 MUST 尽力恢复可解析内容并明确报告丢弃或存疑部分
- **FR-016**: 关闭应用或文件时若存在未保存更改，系统 MUST 提示用户处理
- **FR-017**: 核心功能 MUST 完全离线可用；任何联网能力 MUST 为显式可选且默认关闭

**导出**

- **FR-018**: 系统 MUST 支持导出 .xmind：任务层级、名称、备注与里程碑标记映射为 XMind 可打开、可编辑、可再保存的脑图结构
- **FR-019**: 系统 MUST 支持导出 .vsdx：任务映射为形状、依赖映射为保持逻辑连接的连接线，并承载里程碑与时间线信息，Visio 可打开、可编辑、可再保存
- **FR-020**: 导出产物 MUST 全部为结构化可编辑对象；MUST NOT 以位图或其他不可编辑替身充当导出内容
- **FR-021**: 目标格式无法表达的信息 MUST 显式降级并在导出摘要中逐项告知；MUST NOT 静默丢失

**平台**

- **FR-022**: 全部功能 MUST 在 macOS 与 Windows 上等价可用，两平台交互遵循各自系统惯例

### Key Entities

- **项目规划（Plan）**: 一份完整规划的根对象；名称、描述、格式版本、任务集合、里程碑集合
- **任务（Task）**: 规划的基本单元；名称、父任务（构成层级）、开始/结束日期或工期、负责人、备注、完成状态
- **依赖（Dependency）**: 两个任务间的先后约束（前置 → 后继），默认语义为"前置完成后继才能开始"
- **里程碑（Milestone）**: 具名的时间检查点；名称、日期、关联任务集合
- **校验问题（Validation Issue）**: 一次校验发现的单个问题；严重级别、定位元素、原因说明、修复指引
- **导出摘要（Export Report）**: 一次导出的结果记录；目标格式、成功映射内容、降级项清单

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户在无培训情况下，10 分钟内完成"录入含 20+ 任务的项目描述 → 生成 → 调整编辑 → 保存 → 导出一种格式"全流程
- **SC-002**: 含 1,000 个任务的规划中，视图切换、缩放、拖拽全程无可感知卡顿，常规编辑操作 0.1 秒内可见结果
- **SC-003**: 应用冷启动至可交互不超过 2 秒（95 分位）
- **SC-004**: 导出的 .xmind 在 XMind 当前稳定版中打开成功率 100%，任务层级与文本零丢失，再编辑保存无报错
- **SC-005**: 导出的 .vsdx 在 Visio 2016 及以上版本中打开成功率 100%，形状、连线、文本零丢失且全部可编辑
- **SC-006**: 保存-重开往返 100% 无损；连续 100 次随机编辑后往返仍无损
- **SC-007**: 100% 的校验问题附带元素定位与修复指引
- **SC-008**: 导出中被降级的信息 0 静默丢失——全部出现在导出摘要中
- **SC-009**: 全部验收场景在 macOS 与 Windows 上通过率一致，无平台功能缺口

## Assumptions

- 单用户单机使用；多人协作通过文件分享与版本控制系统完成，实时协同编辑不在本特性范围
- 规划停留在"规划层"粒度：任务、依赖（默认"完成-开始"语义）、里程碑与日历日期（天粒度）；工时、资源分配与成本核算不在本特性范围
- 时间线使用本地日历日期语义，不处理时区与具体时刻
- 导出目标兼容版本：XMind 2020 及以上使用的 .xmind 格式；Microsoft Visio 2016 及以上使用的 .vsdx 格式
- 反向导入（.xmind / .vsdx → 本工具）不在本特性范围
- 自然语言 AI 生成规划不在本特性范围（需求方已确认）；未来如引入，将作为独立特性接入同一规划模型与校验管线
- 首版界面语言为简体中文
- 依据项目宪法：macOS 与 Windows 双平台等价、本地优先离线可用、人类可读原生格式、导出保真为硬约束
