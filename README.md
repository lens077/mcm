# MCM

面向开发者与产品经理的桌面端项目规划工具。写下结构化大纲，得到经校验的规划视图，
并导出为 **XMind 与 Visio 里可以继续编辑**的文件。

> 状态：功能实现完整（63/63 计划任务），自动化质量门全绿。
> 两种导出的真实互操作性与 Windows 平台尚待人工验证 —— 见 [HANDOVER.md](./HANDOVER.md) §6。

## 它解决什么

规划工具往往二选一：要么是纯文本清单（可 diff 但看不出结构），要么是图形工具
（好看但数据锁在私有格式里）。MCM 两边都要：

- **输入即文件**：`.mcm` 的正文就是你写的大纲语法，可手工编辑、可进 Git、行级 diff 稳定
- **四种联动视图**：任务分解、依赖网络、时间线、里程碑 —— 同一模型的四种投影
- **导入现成的图**：架构图截图（本地 OCR）、archify HTML 或 Markdown 里的
  Mermaid 流程图一键转成大纲，之后照常编辑、导出
- **导出可再编辑**：XMind 的依赖是真实连线，Visio 的连接线拖动形状时保持粘连；
  不是位图，不是不可编辑的替身

## 导入现成的图

工具栏「导入图表」把别处画好的架构图 / 流程图转成大纲，载入后照常编辑，
也能直接导出为 XMind、Visio。

| 输入 | 方式 | 精度 |
|------|------|------|
| PNG / JPEG / WebP / BMP 截图 | 本地 OCR，并识别方框、分组框、箭头 | 需要人工核对 |
| archify 生成的 `.html` | 读取其中的节点、连线、分组标注 | 精确 |
| Markdown（`.md`）中的 ` ```mermaid ` 代码块，或 `.mmd` 文件 | 用 mermaid 库解析并渲染预览 | 精确 |

- 方框变成任务（副标题写成备注），分组框变成父任务，箭头变成依赖
- Mermaid 同理：节点变成任务，`subgraph` 变成父任务，箭头变成依赖。
  所有类型的 Mermaid 图都能预览，目前只有 `flowchart` / `graph` 能转成大纲
- 规划模型放不下的内容（连线上的文字、会成环的箭头、图例）写成大纲注释，
  并在导入对话框里逐条列出，不会静默丢弃
- 识别在本机完成，图片不会离开本机

截图识别有两种模型，在导入对话框里切换，选择会被记住：

| 模型 | 获取方式 | 速度（2522×878 截图） | 准确度（26 段文字） |
|------|----------|------------------------|---------------------|
| **快速**（默认）PP-OCRv6 tiny | 内置，开箱即用 | 约 0.3 秒 | 23/26 完全正确，错误只在大小写和标点 |
| **高精度** PP-OCRv6 small | 首次使用时点击下载，21.2 MB | 约 0.7 秒 | 26/26 |

高精度模型不打进安装包，以免超出 25 MB 体积预算。只有你点击「下载」时才会联网：
先从 ModelScope 下载，失败时改用 GitHub，下载后校验 SHA-256，不符就拒绝使用。
无法联网时，也可以手动把两个模型文件放进对话框里提示的目录。两种模型的方框和箭头
识别结果相同，只影响文字。

映射规则、OCR 选型与基准见 [docs/image-import.md](./docs/image-import.md)。

## 快速开始

```bash
make install    # 安装依赖
make dev        # 启动桌面应用
```

没装 `make`（例如 Windows）时用等价的 pnpm 命令：

```bash
pnpm install
pnpm tauri dev
```

运行 `make` 查看全部命令。提交前跑 `make gate`。

在左侧粘贴：

```text
%mcm 1
%title 移动端改版
%start 2026-09-01

- 需求阶段 #t1 @王芳
  - [x] 用户访谈 #t2 [2026-09-01..2026-09-05]
  - 竞品分析 #t3 [3d] <-t2
- 设计阶段 #t4
  - 交互稿 #t5 [5d] <-t3
! 需求冻结 #m1 [2026-09-30] <-t5
```

点「生成规划」。把 `<-t2` 改成 `<-t5` 造个环，看问题面板如何定位。

## 技术构成

| 层 | 选型 | 说明 |
|----|------|------|
| 桌面壳 | Tauri 2.11 | `.dmg` 10.6 MB，冷启动 P95 35 ms |
| 核心 | Rust | 解析、校验、布局、导出全在这里；前端不持有模型状态 |
| 前端 | React 19 + TypeScript strict | Canvas 2D 自研渲染器，1000 任务保持流畅 |
| 导入 | rten + PaddleOCR PP-OCRv6 | 纯 Rust 推理，离线；HTML 解析复用 html5ever |
